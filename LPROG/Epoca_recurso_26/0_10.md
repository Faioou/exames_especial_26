Um **sistema de tipos** é o conjunto de regras da linguagem que diz:

> que tipos de valores podem ser usados em cada operação e que tipo de resultado essa operação produz.

O teu PDF define-o precisamente como uma coleção de regras que associa tipos às partes de um programa e determina, para cada operador, quais os tipos permitidos nos operandos e qual o tipo do resultado. 

# O QUE É UM TIPO

Um tipo diz que género de valor estamos a tratar.

Por exemplo:

```text
int       -> número inteiro
float     -> número real
char      -> carácter
boolean   -> verdadeiro/falso
```

Se tens:

```c
int x;
float y;
```

então:

```text
x tem tipo int
y tem tipo float
```

---

# O QUE É UM OPERANDO

Um **operando** é aquilo sobre o qual um operador atua.

Por exemplo:

```text
3 + 5
```

O operador é:

```text
+
```

Os operandos são:

```text
3
5
```

Outro exemplo:

```text
x * y
```

Operador:

```text
*
```

Operandos:

```text
x
y
```

---

# O QUE FAZ O SISTEMA DE TIPOS

Imagina que a linguagem define esta regra:

```text
integer + integer -> integer
```

Isto significa:

```text
operando esquerdo = integer
operando direito  = integer

resultado = integer
```

Então:

```text
3 + 5
```

é válido:

```text
integer + integer -> integer
```

Resultado:

```text
8
```

do tipo:

```text
integer
```

O teu PDF dá precisamente esta regra como exemplo: se os dois operandos de `+`, `-` ou `*` forem inteiros, o resultado é inteiro. 

---

# EXEMPLO DE ERRO DE TIPOS

Agora:

```c
int x;
x = "ola";
```

Sintaticamente podemos ter uma estrutura válida:

```text
IDENTIFICADOR = EXPRESSÃO ;
```

Mas o sistema de tipos sabe:

```text
x       -> integer
"ola"   -> texto/string
```

Então estamos a tentar fazer:

```text
integer = string
```

Se a linguagem não permitir essa atribuição:

```text
ERRO DE TIPOS
```

É a **análise semântica** que verifica se o programa respeita estas regras do sistema de tipos. O PDF diz que o compilador deve verificar se os tipos dos operandos são legais e compatíveis com a definição do operador. 

---

# LIGAÇÃO COM LÉXICA, SINTÁTICA E SEMÂNTICA

Com:

```c
int x;
x = 3 + 5;
```

a análise léxica reconhece:

```text
int
x
=
3
+
5
;
```

e produz tokens.

A análise sintática verifica que a estrutura está correta:

```text
atribuição
   |
   x = expressão
         |
        3 + 5
```

Depois a análise semântica usa o **sistema de tipos**:

```text
3 -> integer
5 -> integer

integer + integer -> integer
```

Logo:

```text
3 + 5 -> integer
```

E como:

```text
x -> integer
```

temos:

```text
integer = integer
```

✅ válido.

---

# E SE FOR INT + FLOAT?

Por exemplo:

```text
3 + 2.5
```

Temos:

```text
3   -> integer
2.5 -> real
```

Algumas linguagens permitem converter automaticamente o `integer` para `real`:

```text
3      -> 3.0
integer   real
```

ficando:

```text
real + real -> real
```

Isto chama-se **coerção de tipos**, e o teu PDF também fala desta conversão automática.

A frase diz:

> “O sistema de tipos define, para cada operador da linguagem e/ou construção gramatical, os tipos dos operandos e os tipos dos resultados possíveis.”

Isso corresponde diretamente ao que está escrito no teu PDF. 

Logo:

**Verdadeiro ✅**

A frase mais simples para decorar é:

> **Sistema de tipos = regras que dizem que tipos podem ser combinados e que tipo resulta dessa combinação.**
