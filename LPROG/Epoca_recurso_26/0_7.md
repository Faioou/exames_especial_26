Sim. **Esta afirmação é Verdadeira (V)** e aparece praticamente com as mesmas palavras no teu PDF: as tabelas de símbolos são usadas pelos compiladores para armazenar nomes de variáveis, tipos, classes e outras estruturas, juntamente com informação sobre esses elementos. 

# O QUE É UMA TABELA DE SÍMBOLOS?

É uma **estrutura de dados interna do compilador** onde este vai guardando informação sobre os nomes que aparecem no programa.

Pensa nela como uma tabela deste género:

| Nome    | O que é  | Tipo    | Outras informações  |
| ------- | -------- | ------- | ------------------- |
| `x`     | variável | `int`   | endereço, âmbito... |
| `total` | variável | `float` | endereço, âmbito... |
| `Aluno` | classe   | classe  | membros, etc.       |

O PDF diz que, além do nome, uma entrada pode guardar informações como **tipo, endereço, número de referências**, entre outras. 

# EXEMPLO COM UMA VARIÁVEL

Imagina:

```text
int x;
x = 25;
```

Quando o compilador encontra:

```text
x
```

precisa de se lembrar:

> “Existe uma variável chamada `x` e ela é do tipo `int`.”

Pode então ter na tabela:

```text
Nome: x
Tipo: integer
```

Mais tarde, ao chegar a:

```text
x = 25;
```

a análise semântica consulta a tabela e encontra:

```text
x -> integer
```

Como `25` também é inteiro:

```text
integer = integer
```

✅ semanticamente correto.

O teu PDF mostra precisamente que, durante as declarações, o tipo descoberto para um identificador é acrescentado à respetiva entrada da tabela de símbolos. 

# PARA QUE ISTO É ÚTIL?

Agora imagina:

```text
int x;
x = "ola";
```

A estrutura sintática pode estar correta:

```text
IDENTIFICADOR = VALOR ;
```

Mas o compilador consulta a tabela:

```text
x -> integer
```

e vê que:

```text
"ola" -> texto
```

Então:

```text
integer = texto
```

❌ erro semântico.

Portanto, a tabela de símbolos ajuda a análise semântica a responder a perguntas como:

```text
A variável existe?
Que tipo tem?
Já foi declarada?
Está acessível neste ponto do programa?
É uma variável, função, classe, tipo...?
```

O PDF refere precisamente que a tabela também guarda informação sobre o **âmbito (scope)** dos identificadores. 

# E QUEM PREENCHE A TABELA?

Pode começar logo na análise léxica.

Por exemplo, o scanner encontra o lexema:

```text
contador
```

e reconhece:

```text
IDENTIFICADOR
```

Pode criar uma entrada:

```text
contador -> [entrada na tabela]
```

Mais tarde, quando o compilador encontra:

```text
int contador;
```

a análise semântica acrescenta:

```text
contador.tipo = integer
```

O teu PDF diz explicitamente que pode caber ao analisador léxico criar/preencher entradas para identificadores e que, quando se descobre informação nova — por exemplo, o tipo — essa informação é acrescentada à entrada correspondente. 

Portanto, para decorar:

> **Tabela de símbolos = “memória” do compilador sobre os identificadores do programa.**

Por exemplo:

```text
Código:
int idade;
float salario;

Tabela de símbolos:
idade    -> variável, integer
salario  -> variável, real
```

Assim, a afirmação do teste é **Verdadeira ✅**.
