A resposta correta é **c) Transpiler ✅**.

A chave está nesta parte do enunciado:

> recebe um programa em **linguagem de alto nível** e traduz para um formato equivalente **também numa linguagem de alto nível**.

Ou seja:

```text
LINGUAGEM DE ALTO NÍVEL
          ↓
       tradutor
          ↓
LINGUAGEM DE ALTO NÍVEL
```

Isso é precisamente um **transpiler**.

### O que é “linguagem de alto nível”?

É uma linguagem pensada para ser relativamente cómoda para seres humanos programarem, sem termos de escrever diretamente instruções específicas do processador.

Exemplos:

```text
C
C++
Java
Python
JavaScript
TypeScript
```

Portanto, quando a pergunta diz:

> “linguagem de alto nível → linguagem de alto nível”

está a dar-nos a pista principal.

### a) Compilador ❌

No teu PDF, o compilador é definido como um programa que recebe uma **linguagem fonte** e produz uma **linguagem objeto**. O PDF acrescenta que, tipicamente:

```text
Programa fonte
geralmente linguagem de alto nível

        ↓ COMPILADOR

Programa objeto
geralmente código máquina
```



Por exemplo:

```c
x = 3 + 5;
```

pode acabar traduzido para instruções da máquina.

Portanto, na distinção que este exercício está a usar:

> **Compilador: alto nível → normalmente código de nível mais baixo/código máquina.**

Há uma nuance: num sentido muito geral, *compiler* é um termo abrangente para tradução entre linguagens; um transpiler pode ser visto como um tipo de compilador. **Mas nesta pergunta de escolha múltipla querem a designação específica “transpiler”.**

---

### b) Interpretador ❌

Um **interpretador** não tem como objetivo principal produzir outro programa equivalente noutra linguagem.

Ele vai **interpretando/executando o programa**.

Por exemplo, de forma simplificada:

```text
programa
   ↓
INTERPRETADOR
   ↓
executa as instruções
```

Em vez de:

```text
programa A
   ↓
tradutor
   ↓
programa B
```

Portanto não corresponde ao que o enunciado descreve.

**Não encontrei nos PDFs que enviaste uma definição explícita de interpretador**, por isso esta definição é conhecimento adicional.

---

### c) Transpiler ✅

**Transpiler** vem da ideia de *source-to-source translator/compiler*.

Recebe código numa linguagem de alto nível e gera **outro código de alto nível equivalente**.

Por exemplo:

```text
TypeScript
    ↓
transpiler
    ↓
JavaScript
```

Ou:

```text
JavaScript moderno
       ↓
     Babel
       ↓
JavaScript compatível com ambientes mais antigos
```

O objetivo é manter o comportamento do programa, mas representá-lo noutra linguagem ou variante de alto nível.

Portanto:

> **alto nível → alto nível = transpiler. ✅**

**O termo “transpiler” não aparece definido nos PDFs que encontrei**, portanto esta parte é conhecimento adicional necessário para resolver a opção.

---

### d) Crosscompiler ❌

Um **crosscompiler** (*compilador cruzado*) é outra coisa.

É um compilador que **corre numa máquina/plataforma, mas produz código para outra máquina/plataforma**.

Por exemplo:

```text
Computador x86
     ↓
crosscompiler
     ↓
código para ARM
```

Imagina que estás num PC e queres compilar um programa que vai funcionar num microcontrolador ARM.

O importante aqui é:

> **Crosscompiler = a máquina onde compilas é diferente da máquina para a qual estás a gerar código.**

Não significa:

> alto nível → alto nível.

O teu PDF fala na produção de compiladores para diferentes **máquinas concretas**, mas não encontrei nele uma definição explícita de *crosscompiler*. 

### Para o exame, distingue assim

| Termo             | Ideia principal                                |
| ----------------- | ---------------------------------------------- |
| **Compilador**    | alto nível → normalmente código máquina/objeto |
| **Interpretador** | lê e executa o programa                        |
| **Transpiler** ✅  | **alto nível → alto nível**                    |
| **Crosscompiler** | compila numa plataforma para outra plataforma  |

Portanto, **c) Transpiler ✅**, porque o enunciado diz explicitamente que tanto a entrada como a saída estão em **linguagem de alto nível**.
