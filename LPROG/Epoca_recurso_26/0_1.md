Vamos ligar isto diretamente ao exemplo que já tens na cabeça:

```text
x = 25;
```

A ideia é perceber primeiro **onde entra a análise semântica** e só depois atacar a frase do V/F.

O teu PDF coloca as fases assim:

```text
programa fonte
     ↓
análise léxica
     ↓
tokens
     ↓
análise sintática
     ↓
árvore de parse
     ↓
análise semântica
     ↓
árvore de parse anotada
```



## 1. Análise léxica: “que coisas estão escritas aqui?”

Temos:

```text
x = 25;
```

O analisador léxico separa os **lexemas concretos**:

```text
x
=
25
;
```

e classifica-os em tokens:

```text
x     -> IDENTIFICADOR
=     -> ATRIBUIÇÃO
25    -> NÚMERO
;     -> PONTO_E_VÍRGULA
```

O PDF diz precisamente que a análise léxica agrupa os caracteres em tokens que depois são usados pelo analisador sintático. 

Até aqui não estamos a perguntar se `x` existe, se é inteiro, etc.

---

# 2. Análise sintática: “esta sequência tem a forma correta?”

Imagina que a gramática contém:

```text
ATRIBUIÇÃO -> IDENTIFICADOR = NÚMERO ;
```

O parser recebe:

```text
IDENTIFICADOR = NÚMERO ;
```

e conclui:

```text
Está de acordo com a regra da gramática. ✅
```

Portanto:

```text
x = 25;
```

pode estar **sintaticamente correto**.

Se tivesses:

```text
x = ;
```

terias:

```text
IDENTIFICADOR = ;
```

mas a gramática esperava:

```text
IDENTIFICADOR = NÚMERO ;
```

Logo:

```text
erro sintático ❌
```

---

# 3. Então para que serve a análise semântica?

Agora chegamos à parte nova.

A análise sintática consegue dizer:

> “Esta instrução tem a estrutura de uma atribuição.”

Mas há coisas que a gramática sintática, sozinha, não consegue verificar.

Por exemplo:

```text
int x;

x = 25;
```

Isto pode estar:

```text
léxico       ✅
sintático    ✅
semântico    ✅
```

Porque:

* `x` foi declarado;
* `x` é do tipo inteiro;
* `25` é inteiro;
* portanto atribuir `25` a `x` faz sentido.

Agora considera:

```text
int x;

x = "ola";
```

A estrutura continua a ser perfeitamente normal:

```text
IDENTIFICADOR = VALOR ;
```

Portanto pode estar:

```text
léxico       ✅
sintático    ✅
```

Mas semanticamente existe um problema:

```text
x      é inteiro
"ola"  é texto
```

Estás a tentar fazer:

```text
inteiro = texto
```

Logo:

```text
erro semântico ❌
```

E este é exatamente o género de exemplo que aparece no teu PDF:

```text
int x;
x = "ola";
```

Léxica: OK.
Sintática: OK.
Semântica: ERRO. 

---

# 4. Outro exemplo de erro semântico

Considera:

```text
x = 25;
```

A frase pode estar sintaticamente correta.

Mas imagina que `x` **nunca foi declarado**.

Então:

```text
x = 25;
```

tem uma estrutura perfeitamente válida, mas semanticamente:

```text
Quem é x?
Foi declarado?
Que tipo tem?
```

Se não foi declarado:

```text
erro semântico ❌
```

O teu PDF diz que a análise semântica verifica, entre outras coisas:

* se os identificadores foram declarados;
* se há declarações múltiplas incompatíveis;
* os tipos das expressões e variáveis;
* a compatibilidade dos tipos. 

Portanto podes pensar:

```text
ANÁLISE LÉXICA
"Reconheço estes pedaços?"

ANÁLISE SINTÁTICA
"Estes pedaços estão organizados
segundo as regras da linguagem?"

ANÁLISE SEMÂNTICA
"Esta construção, apesar de estar
bem escrita, faz sentido na linguagem?"
```

# 5. Agora entram os “atributos”

É aqui que a pergunta do exame começa.

O compilador precisa de guardar informação sobre aquilo que encontrou.

Por exemplo, para:

```text
25
```

pode guardar:

```text
valor = 25
tipo  = inteiro
```

Para:

```text
x
```

pode guardar:

```text
nome = "x"
tipo = inteiro
```

Essas informações chamam-se **atributos**.

O PDF define atributos como valores associados aos símbolos da gramática e dá exemplos como:

```text
tipo
valor
nome
endereço
```



Portanto:

```text
NÚMERO
  |
  ├── valor = 25
  └── tipo = inteiro
```

O `valor` e o `tipo` são atributos.

---




Sim — aqui há uma distinção importante. **Os atributos não são simplesmente “atributos dos lexemas” e não são todos criados na análise semântica.**

O teu PDF diz duas coisas que juntas esclarecem isto:

* na **análise semântica**, os atributos são “valores associados a cada símbolo (terminais e não-terminais) da gramática”; 
* o **analisador léxico** pode já devolver um token acompanhado de informação adicional, como o lexema ou o valor. O próprio PDF mostra uma estrutura de token com `lexeme` ou `value` como atributo. 

Vamos usar sempre o mesmo exemplo:

```text
x = 25;
```

### 1. Primeiro, análise léxica

O scanner encontra os lexemas concretos:

```text
x
=
25
;
```

e produz tokens:

```text
x     -> IDENTIFICADOR
=     -> ATRIBUIÇÃO
25    -> NÚMERO
;     -> PONTO_E_VÍRGULA
```

Mas o scanner não precisa de mandar apenas:

```text
NÚMERO
```

Pode mandar algo equivalente a:

```text
token = NÚMERO
valor = 25
```

Porque saber apenas que aquilo é um `NÚMERO` perderia uma informação importante: **qual número era?**

Do mesmo modo, para:

```text
x
```

pode devolver algo equivalente a:

```text
token = IDENTIFICADOR
lexema = "x"
```

O PDF mostra precisamente essa ideia:

```text
struct TokenRecord {
    TokenType kind;
    int linenum;
    union {
        char *lexeme;
        int value;
    } attribute;
}
```

Ou seja, **já durante a análise léxica um token pode vir acompanhado de um atributo**. 

---

### 2. Então `25` é o atributo?

Não.

Temos de distinguir:

```text
25
```

é o **lexema** — os caracteres concretos escritos no programa.

```text
NÚMERO
```

é o **token** — a categoria em que `25` foi classificado.

E podemos ter:

```text
NÚMERO.valor = 25
```

Aqui `valor` é um **atributo do token/símbolo terminal `NÚMERO`**, cujo valor foi obtido a partir do lexema `25`.

Portanto:

```text
lexema:            25
                     ↓
análise léxica reconhece
                     ↓
token:             NÚMERO
                     ↓
atributo:          valor = 25
```

Não diríamos rigorosamente:

> “25 tem o atributo 25”.

Diríamos:

> **O token `NÚMERO` correspondente ao lexema `25` possui o atributo `valor = 25`.**

---

### 3. E depois, na análise semântica?

É aí que os atributos passam a ser usados de forma muito mais ampla.

O PDF diz que na análise semântica os atributos podem estar associados **tanto a terminais como a não terminais**. 

Imagina uma gramática simplificada:

```text
EXPRESSÃO -> NÚMERO
```

Temos na árvore:

```text
       EXPRESSÃO
            |
         NÚMERO
           25
```

O scanner já pode ter dado:

```text
NÚMERO.valor = 25
```

Depois uma ação semântica pode fazer:

```text
EXPRESSÃO.valor = NÚMERO.valor
```

Então:

```text
       EXPRESSÃO
       valor = 25
            ↑
            |
         NÚMERO
         valor = 25
```

Aqui acontece algo muito importante:

* `NÚMERO.valor` pode ter vindo **do analisador léxico**;
* `EXPRESSÃO.valor` é calculado/propagado através das **ações semânticas**.

O PDF tem exatamente um exemplo deste género com dígitos: pressupõe que o analisador léxico devolve para o token `digit` um atributo `dval`, e depois as ações semânticas usam esse `dval` para calcular os atributos `val` dos não terminais. 

---

### 4. Vamos usar `x = 25;`

Podemos imaginar:

```text
x = 25;
```

Análise léxica:

```text
lexema "x"
    ↓
IDENTIFICADOR
nome = "x"

lexema "25"
    ↓
NÚMERO
valor = 25
```

Depois a análise sintática constrói algo semelhante a:

```text
              ATRIBUIÇÃO
             /     |      \
   IDENTIFICADOR   =     NÚMERO
         x                  25
```

Agora a análise semântica pode precisar de saber:

```text
IDENTIFICADOR.nome = "x"
NÚMERO.valor = 25
```

e consultar a tabela de símbolos para descobrir:

```text
x.tipo = inteiro
```

Depois pode determinar:

```text
NÚMERO.tipo = inteiro
```

e verificar:

```text
tipo de x     = inteiro
tipo de 25    = inteiro

inteiro = inteiro  ✅
```

Portanto a atribuição faz sentido.

---

### 5. Os não terminais também têm atributos

Esta é a parte que responde diretamente à tua dúvida.

Os atributos **não pertencem apenas aos tokens nem aos lexemas**.

Por exemplo:

```text
EXPRESSÃO -> EXPRESSÃO + TERMO
```

podemos ter:

```text
EXPRESSÃO.tipo
EXPRESSÃO.valor
TERMO.tipo
TERMO.valor
```

`EXPRESSÃO` e `TERMO` são **não terminais**, não são lexemas.

Mesmo assim têm atributos.

O PDF é explícito: os atributos são associados aos **símbolos terminais e não terminais da gramática**. 

---

### Portanto, a resposta curta é

**Onde são criados os atributos?**

Não existe uma única resposta para todos:

```text
ANÁLISE LÉXICA
    ↓
pode fornecer atributos dos TOKENS
obtidos diretamente do lexema

Ex.:
NUM.valor = 25
ID.lexema = "x"
```

Depois:

```text
ANÁLISE SEMÂNTICA
    ↓
usa esses atributos e calcula/propaga
outros atributos nos símbolos da gramática

Ex.:
EXPRESSÃO.valor = 25
EXPRESSÃO.tipo = inteiro
```

E à pergunta:

> **“São atributos dos lexemas?”**

A resposta mais correta é **não**.

> **Na teoria da análise semântica do teu PDF, são atributos dos símbolos da gramática — terminais e não terminais. No caso dos terminais/tokens, alguns desses atributos podem ser obtidos a partir do lexema pelo analisador léxico.**

O exemplo do PDF com `digit.dval` mostra exatamente essa ligação: o scanner lê um dígito concreto, fornece o seu valor como atributo do token `digit`, e depois a análise semântica usa-o para calcular atributos dos não terminais. 



















































# 6. E o que são “ações semânticas”?

São as operações que usam esses atributos para:

* calcular coisas;
* verificar tipos;
* detetar erros;
* produzir nova informação.

O PDF distingue precisamente:

```text
ATRIBUTOS = informação

AÇÕES SEMÂNTICAS = aquilo que fazemos com essa informação
```



Por exemplo:

```text
3 + 5
```

Podemos ter uma regra simplificada:

```text
E -> E + T
```

e uma ação semântica:

```text
E.val = E1.val + T.val
```

Se:

```text
E1.val = 3
T.val  = 5
```

então a ação calcula:

```text
E.val = 3 + 5
      = 8
```

Este é também o exemplo usado no teu PDF. 

---

# 7. Agora precisamos de perceber “filhos” e “pai”

Imagina esta pequena parte de uma árvore de parse:

```text
           E
         / | \
        E  +  T
        |     |
        3     5
```

O `E` de cima é o **pai**.

Os símbolos imediatamente abaixo são os seus **filhos**.

Então podemos ter:

```text
             E
          val = 8
           /    \
          /      \
     E             T
   val=3          val=5
```

O valor `8` do pai foi calculado usando os valores dos filhos:

```text
8 = 3 + 5
```

---

# 8. O que é um atributo sintetizado?

Agora chegamos ao termo central da pergunta.

Um atributo é **sintetizado** quando a informação sobe:

```text
FILHOS
   ↓
   ↓ informação
   ↓
 PAI
```

Mais concretamente:

```text
        E.val = 8
           ↑
          / \
         /   \
   E.val=3   T.val=5
```

O atributo do pai depende dos atributos dos filhos.

No exemplo:

```text
E.val = E1.val + T.val
```

ou seja:

```text
8 = 3 + 5
```

O PDF diz explicitamente:

> Os atributos sintetizados dependem apenas dos atributos dos filhos numa árvore de parse. 

Guarda portanto:

```text
SINTETIZADO

filhos  --->  pai
```

---

# 9. E o que é S-attributed?

Agora já consegues perceber.

Se **todas as ações semânticas da gramática** só calcularem atributos desta maneira:

```text
filhos -> pai
```

ou seja, só houver atributos sintetizados, então a gramática estendida chama-se:

```text
S-attributed
```

O próprio PDF diz:

> se em todas as ações só houver atributos que dependam dos atributos dos filhos, a gramática é **S-attributed** e esses atributos são **sintetizados**. 

---

# 10. Então analisemos agora a frase do exercício

A afirmação diz:

> “Na análise semântica, se todas as ações de uma gramática envolverem apenas atributos que dependem dos atributos dos filhos na árvore de parse, diz-se que essa gramática é **L-attributed**, e que esses atributos são sintetizados.”

Vamos separar em duas partes.

### Primeira parte

Diz:

```text
atributos dependem apenas dos filhos
        ↓
atributos sintetizados
```

✅ **Isto está correto.**

### Segunda parte

Diz que, nessa situação, a gramática é:

```text
L-attributed
```

❌ **É aqui que está o problema segundo a terminologia usada no teu PDF.**

O PDF chama a essa situação:

```text
S-attributed
```

Não `L-attributed`. 

Portanto a frase deveria dizer:

> “...diz-se que essa gramática é **S-attributed**, e que esses atributos são sintetizados.”

Assim estaria correta.

## Portanto, no exercício:

**Resposta: FALSO.**

Porque:

```text
Só depende dos filhos
        ↓
atributos sintetizados
        ↓
gramática S-attributed
```

e não:

```text
gramática L-attributed
```

---

### Para decorar

Pensa na direção em que a informação anda:

```text
          PAI
           ↑
           ↑
     informação sobe
           ↑
        FILHOS

= atributo SINTETIZADO
= S-attributed, se todos forem assim
```

Mais tarde, quando estudarmos **atributos herdados**, vais ver o contrário: informação que pode vir do pai ou de um símbolo à esquerda. É aí que entra a noção de **L-attributed** no teu PDF.
